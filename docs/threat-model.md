# Threat model

This document lists what TorrentPlayer protects, who might attack it, and the controls that address each
threat. Controls marked ✅ are implemented; the rest are required for the phase shown and are
tracked here so they can be reviewed as each phase lands.

## Assets

- The user's machine: files outside TorrentPlayer's storage directory, and the ability to run code.
- The user's network privacy: their real IP address when a VPN, tunnel, or proxy is selected.
- Secrets: WireGuard private keys and proxy credentials.
- Integrity of TorrentPlayer itself: the code users install and its update channel.

## Trust boundaries

```text
 Internet (peers, trackers, DHT, web)   ── untrusted ──►  torrentplayer-net / torrentplayer-torrent
 Torrent metadata, media, subtitles     ── untrusted ──►  torrentplayer-swarm / torrentplayer-media / webview player / FFmpeg
 Other local processes and websites     ── untrusted ──►  loopback HTTP server, IPC
 Webview (frontend)                     ── untrusted ──►  Tauri IPC commands
 Build and release pipeline             ── must be trusted ──► users' machines
```

## Threats and controls

### Malicious torrents and media

| Threat                                                                                                                                                                                                                                                                                                                          | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Status    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| Path traversal via file names in torrent metadata (`..`, absolute paths, Windows reserved names such as `CON`, symlinks) writes outside the storage directory.                                                                                                                                                                  | Sanitize every path component; resolve and verify the final path is inside the storage root; reject rather than rewrite suspicious names. Fuzzed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Phase 1   |
| Oversized or deeply nested metadata, huge file counts, or giant subtitle files exhaust memory.                                                                                                                                                                                                                                  | Size and count limits on metadata (16 MiB `.torrent` files, 50 000 files), URLs, and subtitles. A `.torrent` file whose piece length is 0 or above 64 MiB, with no data, or whose file lengths overflow is refused before either engine parses it further. Partly downloaded pieces share one 256 MiB budget across all torrents of the engine.                                                                                                                                                                                                                                                                        | Phase 1/3 |
| Subtitle text from a torrent or a chosen file injects markup or script into the webview, or a crafted subtitle file (huge lines, millions of cues, odd encodings, hostile `<`/`{` runs) exhausts memory or CPU.                                                                                                                 | Parsed in Rust (`torrentplayer-media`), never in the webview: at most 5 MiB, 20 000 cues, 600 characters and 8 lines per cue; linear-time markup removal; plain text only (tags, ASS overrides, and control characters removed). The player adds cues as `VTTCue`s with `&`, `<`, `>` escaped, never as HTML, and needs no URL or CSP change. Files are fetched at background priority with a 60 s timeout. Fuzzed with proptest.                                                                                                                                                                                      | Phase 1   |
| Container headers (MP4, Matroska) crafted to make the track probe loop, recurse, or read the whole file.                                                                                                                                                                                                                        | Fixed walk paths, sizes checked against parents, limits on boxes, elements, tracks, and reads (48 × 64 KiB); 45 s timeout. Fuzzed with proptest.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Phase 1   |
| Malformed media exploits decoder bugs in libmpv/FFmpeg.                                                                                                                                                                                                                                                                         | Keep bundled libmpv/FFmpeg current; track their advisories; run decoding in libmpv rather than custom parsers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Phase 2   |
| Media probed by the user's own FFmpeg (`ffprobe` for durations, `ffmpeg` for seek-bar thumbnails) is a playlist or references other files or hosts (HLS, DASH, concat, MOV data references), making FFmpeg read local files or reach the network around the network mode and kill switch; or it exploits an FFmpeg decoder bug. | FFmpeg runs as a separate process with `-protocol_whitelist http,tcp` and a `-format_whitelist` of plain media containers (no playlist or image-sequence demuxers; tested against HLS and concat inputs), reading only a loopback stream URL that serves already-downloaded bytes, with no standard input, an 8–20 s time limit, and bounded output (a whole JPEG of at most 512 KiB, or 64 KiB of JSON parsed into bounded numbers). Its errors are logged without the URL's token. It is optional and off when not installed. Keeping it current is the user's (or their package manager's) job until it is bundled. | ✅        |
| The FFmpeg command line (visible to other local programs) leaks the stream server's token.                                                                                                                                                                                                                                      | Each FFmpeg run gets a stream published under a token of its own, which opens only that stream and only until the run ends (`StreamServer::publish_private`); the session token never leaves the app.                                                                                                                                                                                                                                                                                                                                                                                                                  | ✅        |
| A compromised webview points `advanced.ffmpegDir` (or `storage.downloadDir`) at a network share or a download folder, so a program from there runs on every stream start, or Windows sends the user's NTLM hash to the share when the folder is checked.                                                                        | `update_settings` refuses new values for both folders; only the native pickers (`choose_ffmpeg_dir`, `choose_download_dir`) set them. UNC, `\\?\` and `\\.\` paths are refused on load and on save before any file system access, and an FFmpeg folder inside a download folder (which holds the engine caches) is refused. Tested by settings and app tests.                                                                                                                                                                                                                                                          | ✅        |
| Hostile URL schemes (`file:`, `javascript:`) in user-supplied links.                                                                                                                                                                                                                                                            | Only `http`, `https`, and `magnet` are accepted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Phase 1   |
| A pasted link, a search result, or a torrent makes the app send requests into the user's local network (a router's admin page, a cloud metadata address) through a `.torrent` link, its redirects, or an HTTP tracker.                                                                                                          | `.torrent` links and every redirect they send must lead to public hosts: names and addresses that are `localhost`, loopback, private, or link-local are refused in every network mode, redirects are followed at most 5 times, only to http(s), and never from https to http. HTTP tracker announces (also after redirects) are refused for the same addresses. UDP trackers at local addresses, and librqbit's own tracker requests with the `rqbit` engine in Direct mode, are not covered yet.                                                                                                                      | Partial   |
| The FFmpeg sidecar (audio conversion) is exploited by malformed media.                                                                                                                                                                                                                                                          | A separate process started without a shell; a minimal build with only the Matroska and MOV demuxers, five audio decoders, the AAC encoder, the MP4 muxer, and loopback HTTP input; pinned, checksummed source kept current; the MSE type is derived from its output by a bounded parser; input protocols and formats are whitelisted, stderr lines are capped at 2 KiB, pending conversions are cancelled on a new seek or stop; the process is stopped when its output is no longer read.                                                                                                                             | ✅        |

### Local attackers

| Threat                                                                                                                                                                           | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Status  |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| Another local app or a website (via DNS rebinding) reads streams from the loopback HTTP server.                                                                                  | Bind to `127.0.0.1` only; random port; random per-session token compared in constant time; validate the `Host` header; no permissive CORS; strict `Range` parsing with limits.                                                                                                                                                                                                                                                                                                                                                                           | Phase 1 |
| Another local app holds the loopback HTTP server's connections open so the player cannot get one, or a client that stopped reading keeps its connection forever.                 | Connections that have not authenticated are kept apart from the player's: at most 8 (the oldest is closed for a new one), each closed if it has not authenticated within 10 seconds or once it is refused. Authenticated connections take one of 16 slots; when none is free, one that has read and written nothing for 30 seconds is closed to make room.                                                                                                                                                                                               | ✅      |
| Secrets read from config files or logs.                                                                                                                                          | OS keychain storage; zeroizing in-memory types; redaction in `Debug`, logs, and errors.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Phase 5 |
| Library database read by other users.                                                                                                                                            | It lives in the per-user app-data directory; on Unix the directory is forced to `0700` and `library.sqlite3` to `0600`.                                                                                                                                                                                                                                                                                                                                                                                                                                  | ✅      |
| SQL injection via course titles or file names.                                                                                                                                   | Every stored value uses a SQLite query parameter; schema and query text are static. Regression-tested with SQL-shaped titles.                                                                                                                                                                                                                                                                                                                                                                                                                            | ✅      |
| Another local user reads the URL token on the FFmpeg sidecar's command line (process listings show arguments).                                                                   | The URL is for a loopback server of its own that serves only the file being converted, with its own token, and stops with the stream; it grants nothing on the app's main stream server. FFmpeg's log lines are kept with the token removed.                                                                                                                                                                                                                                                                                                             | ✅      |
| A crash, a failing disk, or another local program alters the engine's piece cache (`pieces.dat`, `pieces.idx`), so that wrong bytes are played or sent to peers after a restart. | Pieces kept from an earlier session are checked against the torrent's SHA-1 hashes before any byte of them is read or uploaded: up front after a crash, and on first read after a clean quit (whose marker holds only while the cache file keeps its length and modification time); one that fails is downloaded again. Index records carry a checksum and are checked against the torrent and the cache file's size; an index too large, in another format, or for another torrent is not read. Tested by `torrentplayer-swarm` store and engine tests. | ✅      |

### Compromised or buggy frontend

| Threat                                                                  | Control                                                                                                                                                                  | Status  |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| Script injection (for example through a course title rendered as HTML). | Strict CSP: `script-src 'self'`, no inline scripts, no `eval`; Svelte escapes text by default; `{@html}` is banned in review.                                            | ✅      |
| Injected script calls powerful backend commands.                        | Every command must be declared in `build.rs` and granted in a capability file; the main window has only the permissions it needs; Tauri's prototype freezing is enabled. | ✅      |
| Remote pages gain IPC access.                                           | No remote URLs in any capability; the webview loads only bundled assets; the asset protocol is disabled.                                                                 | ✅      |
| The frontend sends malformed arguments.                                 | Every IPC command validates its arguments in Rust.                                                                                                                       | Ongoing |

### Network privacy

See [Network modes and kill switch](network.md) for the design.

| Threat                                                                                                                                                                                                                                                        | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Status                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| Tunnel or proxy drops and traffic leaks over the direct connection.                                                                                                                                                                                           | Every connection (peers, trackers, `.torrent` downloads, search, connection check) goes through `torrentplayer-net`; protected modes block until verified and whenever the 5-second health check fails (two checks in a row for a connected SOCKS5 proxy; for WireGuard, 20 s without an answer or no current session), close existing connections and their tunnel relays (epoch leases), re-check the lease before every dial, and never fall back to direct. Tested by stopping a proxy mid-download, a WireGuard server that stops answering, and a switch to a protected mode during a host-name lookup.                           | ✅ (SOCKS5, WireGuard) |
| A connection made under the old mode survives a mode change (pooled HTTP connection, librqbit session).                                                                                                                                                       | Mode changes start a new epoch that closes every leased connection, including those relayed by the loopback bridge; librqbit is stopped before protection turns on or off.                                                                                                                                                                                                                                                                                                                                                                                                                                                              | ✅                     |
| UDP (DHT, UDP trackers, uTP, local discovery) bypasses the proxy or tunnel.                                                                                                                                                                                   | No native unbound UDP in protected modes: uTP and local discovery off; librqbit gets magnet links with no trackers. Scoped DHT and trackers use WireGuard datagrams/DNS or SOCKS5 UDP ASSOCIATE with a relay-connected socket and live TCP control connection. Public node/peer and tracker source checks, strict UDP framing, and epoch revocation apply; unsupported UDP never falls back. Remote target DNS stays at the proxy; librqbit contacts no trackers in protected modes (TorrentPlayer announces for it). `.torrent` files refused by librqbit. Tested with scripted relays and direct UDP sinks that must receive nothing. | ✅                     |
| DNS queries for trackers or search reveal activity outside the tunnel.                                                                                                                                                                                        | SOCKS5: host names resolved by the proxy (`socks5h`). WireGuard: resolved by the tunnel's DNS servers. librqbit gets no trackers in these modes; TorrentPlayer announces to them through the bridge with names unresolved (tested: a tracker named `localhost` reaches the proxy by name). Direct with a VPN app: system resolver (depends on the VPN app's DNS). Documented.                                                                                                                                                                                                                                                           | ✅                     |
| A listening port accepts peers outside the selected mode, revealing the real IP address to them or receiving traffic around the tunnel.                                                                                                                       | Off by default. When turned on, `torrentplayer-net` opens it only on the mode's path: every interface in direct mode, or the WireGuard tunnel's addresses inside the tunnel; never in SOCKS5 mode (no safe place to listen). Closed while the kill switch blocks traffic and reopened per epoch; accepted connections hold epoch leases and close on mode changes. IPv6 only with "IPv6 through the tunnel". librqbit's own listener (not pinnable) is used only in direct mode. UPnP mapping only in direct mode. Tested on loopback and inside a test WireGuard tunnel.                                                               | ✅                     |
| Incoming connections exhaust resources or confuse the engine (handshake floods, connections for other torrents, peer-limit bypass).                                                                                                                           | At most 64 queued and 32 handshaking connections, each with the handshake timeout; strict handshake parsing; unknown info hashes, paused torrents, self-connections, and addresses banned for bad data refused; the per-torrent peer limit counts incoming peers.                                                                                                                                                                                                                                                                                                                                                                       | ✅                     |
| A peer sends bad data to stall playback: garbage blocks for pieces other peers are fetching, so that pieces keep failing their hash check and the sources tie.                                                                                                | TorrentPlayer's engine accepts a block only from the peer it asked for it (or recently cancelled there). A failed piece is fetched again from one peer where possible, and each block's SHA-1 is kept with its sender (at most 64 pieces); once the piece verifies, every peer whose block differed is banned ("smart ban") and no other. A peer alone behind two bad pieces is banned too. Bans close the connection and refuse its IP address for outgoing and incoming connections.                                                                                                                                                  | ✅                     |
| IPv6 bypasses an IPv4-only tunnel.                                                                                                                                                                                                                            | IPv6 destinations refused in protected modes unless the user selects IPv6 through the tunnel.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | ✅                     |
| An update removes a protection the user relied on (the VPN adapter mode, removed in 0.3.0), so traffic silently goes out directly.                                                                                                                            | Settings that used it migrate to Direct with `network.hold = "vpnAdapterModeRemoved"`; until the user dismisses the notice (Settings → Network & VPN and the status bar) or picks SOCKS5 or WireGuard, the network manager holds all traffic (`NetworkConfig::hold`: state `error`, kill switch engaged, librqbit started behind the bridge). The migration is saved at once and applies to files of any version. Tested by settings migration, app mapping, and network manager tests.                                                                                                                                                 | ✅                     |
| A damaged or unreadable `settings.json`, or one whose `network.mode` this version does not know (a typo, a newer version), falls back to the defaults, so a SOCKS5 or WireGuard user silently connects directly, and the next save overwrites their settings. | Loading sets `network.hold = "settingsUnreadable"` whenever the file exists but cannot be read or parsed, or its network section or mode is invalid: Direct mode is held like the removed-mode case until the user confirms a connection. Other network values are read one by one, so a single bad value never resets the mode. The original is copied to `settings.invalid.json` and nothing is written while loading; if the copy fails, saves are refused. A missing file (first run) still starts in Direct. Tested by settings store and app mapping tests.                                                                       | ✅                     |
| Another local program uses TorrentPlayer's loopback SOCKS5 bridge as an open proxy into the VPN.                                                                                                                                                              | Listens on `127.0.0.1` only; RFC 1929 password is a random per-run token compared in constant time; only `CONNECT`; the token is never logged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | ✅                     |
| Malicious proxy replies exploit the SOCKS5 client.                                                                                                                                                                                                            | Strict parser: every version, reserved byte, length, and address type checked; nothing read past the reply; parser tests for malformed replies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | ✅                     |
| WireGuard private key leaks from an imported file (logs, UI, errors).                                                                                                                                                                                         | The parser keeps keys in zeroizing, Debug-redacted `Secret`s; summaries and errors never contain them; the imported text is wiped after parsing; keys are stored in the OS credential store; script hooks are never run.                                                                                                                                                                                                                                                                                                                                                                                                                | ✅                     |
| The WireGuard peer cannot authenticate or the tunnel becomes unavailable.                                                                                                                                                                                     | The mode requires an authenticated handshake, blocks traffic on missing keys, stale handshakes, or a server that stops answering tunnel traffic (20 s without an authenticated reply; idle and blocked tunnels are probed with one tiny packet inside the tunnel, with or without a DNS server, and a tunnel left unanswered for 6 minutes is replaced), and closes connections on mode changes; it never connects directly. Tested with a server that never answers and one that stops and resumes, with and without a usable DNS server.                                                                                              | ✅                     |
| The public-IP check reveals the user's address.                                                                                                                                                                                                               | Two requests to icanhazip.com (IPv4 and IPv6) through the current mode, without identifiers: for the status bar at start-up, on connection changes, and every 10 minutes (turn off with `network.showPublicIp`), and when Check is clicked; refused without sending anything while the kill switch is engaged. Disclosed in the README.                                                                                                                                                                                                                                                                                                 | ✅                     |

### Memory safety

| Threat                                        | Control                                                                                                                                                                                                                                                                                                                                                              | Status  |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| Memory corruption in Rust code.               | `unsafe` forbidden in every library crate except `torrentplayer-player` (denied, for its planned FFI). `torrentplayer-app` denies it, with one documented exception: `set_memory_target` in `src-tauri/src/window.rs` (two WebView2 COM calls on the main thread, with `// SAFETY:` comments); its binary forbids it. The vendored `tokio-wireguard` forbids it too. | ✅      |
| Memory corruption at the libmpv FFI boundary. | Minimal, encapsulated `unsafe` with `// SAFETY:` comments; panics caught at the boundary; AddressSanitizer in CI.                                                                                                                                                                                                                                                    | Phase 2 |

### Search providers

| Threat                                                                                                                                        | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Status  |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| A malicious or compromised search provider returns oversized, malformed, or script-bearing responses.                                         | Per-provider timeouts and size limits; strict, bounded parsing of the event stream (event, stream, result, and time limits; see IPC); results rendered as text only; download links kept only on the provider's own host (they are followed to preload the best pick), with the 16 MiB `.torrent` limit, public hosts only (no local-network addresses or names, also after redirects, also in direct mode) and http(s)-only redirects without https-to-http downgrades, and never logged; one failing provider never blocks others. | Phase 4 |
| User-added providers execute code.                                                                                                            | Providers are declarative definitions (Torznab-compatible endpoint or URL template + mapping); executable plugins are never loaded.                                                                                                                                                                                                                                                                                                                                                                                                  | Phase 4 |
| Search queries leak the user's IP when a VPN is selected.                                                                                     | Search traffic uses the selected network mode, and the kill switch applies.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | ✅      |
| Provider API keys exposed.                                                                                                                    | Stored in the OS keychain.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Phase 4 |
| The default search service (search.emberglow.tech, behind Cloudflare) sees every query and the user's IP (or the VPN's).                      | Disclosed in the README; search uses the selected network mode; no account or identifier is sent; users can disable the provider.                                                                                                                                                                                                                                                                                                                                                                                                    | Phase 4 |
| Search results link to unlicensed, mislabeled, or malicious content (fakes, wrong sizes, adult content).                                      | Results are labeled with source, indexer, and "License unknown"; adult categories excluded by default; sizes shown; nothing is downloaded until the user picks a file; all torrent metadata passes the path and size checks.                                                                                                                                                                                                                                                                                                         | Phase 4 |
| A torrent's picture (used as a thumbnail) is malformed, oversized, or not an image (SVG with scripts, HTML, an exploit for an image decoder). | Only JPEG, PNG, or WebP files of at most 2 MiB (8 MiB of pieces) are chosen, never SVG; pieces are hash-checked; the bytes must start like one of those formats; they reach the webview only as a `data:` URL in an `<img>`, which the content security policy limits to `'self'` and `data:`; the decoding is the webview's own. No outside poster service is asked.                                                                                                                                                                | ✅      |

### Supply chain

| Threat                              | Control                                                                                                                                                                                 | Status                             |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| Vulnerable or malicious dependency. | Lockfiles committed; `cargo deny` (advisories, licenses, bans, sources) and `npm audit` on every PR and daily; Dependabot with a 14-day cooldown; new dependencies justified in review. | ✅                                 |

## Non-goals

- Protecting a user from an attacker who already controls their OS account.
- Anonymity against a global network adversary. A VPN hides the user's IP from peers; it does not
  make BitTorrent anonymous.
